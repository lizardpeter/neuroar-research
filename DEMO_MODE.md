# NeuroAR public demo library and gesture AR

**Research / educational visualization only. Never use for clinical decisions,
neurosurgical procedures, physical-head registration, or instrument navigation.**

## Try it without any real person

1. Open the **Study** tab and choose **Demos → Real CT and MRI demo library**.
2. Select one Slicer sample scan (for example **Head CT** or **Head MRI · T1**).
   A first-use download requires network access; successive reads use a
   local iOS cache. The app validates the original SHA-256 of the file.
3. Open **Studio** for a full-screen, camera-free 3D volume preview.
   One-finger orbit and two-finger pinch use SceneKit camera controls.
4. Open **Demo AR** to display the currently selected scan's physical
   orthogonal slices in world-tracked AR at an approximate tabletop distance.
   This does not require a face or a real head.

The translucent scalp/skull ellipsoids in Demo AR are deliberately marked as
**schematic**. They are **not** generated by clinical anatomical segmentation.
The optional intensity-threshold mesh comes from the current image but is **not**
a validated segmented skull or brain. No CT/MRI co-registration occurs.

## Controls in Demo AR

- **One-finger touch drag:** rotate around two axes.
- **Two-finger touch drag:** move the virtual object in the view plane.
- **Two-finger pinch:** scale the virtual object.
- **Two-finger twist:** roll the virtual object.
- **One in-air thumb/index pinch:** move the object in the image plane.
- **Two in-air thumb/index pinches:** separate/close hands to scale; twist to
  rotate. This uses Apple Vision's **2D** hand landmarks from the rear camera.
  No 3D finger position, hand depth or surgical-grade pose is measured.

A recenter control resets placement and transformations. Disabling the hand
toggle removes the camera hand-detection workload. The separate **Live AR**
patient-facing research mode remains unchanged and uses its independent,
unvalidated face/LiDAR registration gate.

The Demo AR camera is paused when that tab is not active or the app is
backgrounded. Studio has no camera requirement.

## Public research datasets (never automatically downloaded)

The built-in selection list uses 3D Slicer's immutable SHA-256-addressed
samples, hosted by the Slicer project. It links six 3D scalar NRRDs:

| Entry | SHA-256 provenance | Relationship |
| --- | --- | --- |
| Head CT | Slicer CTMRBrain CT-brain.nrrd | CT–MR Brain example |
| Head MRI T1 | Slicer CTMRBrain MR-brain-T1.nrrd | Same example |
| Head MRI T2 | Slicer CTMRBrain MR-brain-T2.nrrd | Same example |
| Full head MRI | Slicer MRHead MR-head.nrrd | Independent MRI |
| Cone-beam head CT | Slicer CBCTMRHead DZ-CBCT.nrrd | CBCT–MR Head example |
| MRI for CBCT head | Slicer CBCTMRHead DZ-MR.nrrd | Same CBCT example |

Original source and attribution:
- https://github.com/Slicer/Slicer/blob/main/Modules/Scripted/SampleData/SampleData.py
- https://github.com/Slicer/SlicerTestingData
- https://slicer.readthedocs.io/en/latest/user_guide/modules/sampledata.html

These examples are public educational/research data. They are **not** generic
anonymized patient templates for diagnosis, and matched modalities must not
be assumed co-registered without a verified transform.

Additional large source, linked from the Demo Library:
[University of Utah SCI Head Model](https://sci.utah.edu/sci-head-model/)
(high-resolution T1/T2, segmentation, and meshes). This may require external
resampling or format conversion for mobile memory limits. Its multi-gigabyte
meshes and full-resolution segmentation are **not** automatically downloaded
or represented as if they work within NeuroAR yet.

## Supported data

- Existing NIfTI-1 \`.nii\` and \`.nii.gz\` importer; existing supported DICOM.
- New embedded scalar 3D NRRD \`.nrrd\` import with **raw or gzip** encoding,
  explicit millimeter RAS/LPS physical axes and scalar integer/float data.
- Large NRRD data is **integer-stride downsampled** to at most 12 million
  retained voxels. It preserves grid orientation and retained-voxel positions;
  it is *not* full-resolution interpolation or clinically valid resampling.
- Existing masks still require exactly matching grid dimensions and affines.
  A downsampled scan requires separately prepared, matching ROI masks.
- No general vector DWI, time series, \`.nhdr\` detached payloads,
  non-mm units, or unsupported transfer syntax.
- No true 3D mesh-based bone/scalp segmentation from public datasets yet.

## Privacy and distribution

Public example scans are fetched with HTTPS only when selected, verified
against the expected SHA-256, cached locally, and not bundled into the public
GitHub repository. User-imported medical images are never uploaded by this
demo. Delete cached downloads via the OS's app-storage controls if needed.

After development changes are merged, **TestFlight is still released manually**
via GitHub Actions. An ordinary CI pass does not install a new version.
